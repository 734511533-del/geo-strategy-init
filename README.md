# GEO Strategy Init · GEO 策略研判技能

> 一句话：当消费者开始问 AI「哪个牌子好」，你的品牌在 AI 的回答里存在吗？这个技能帮你把这件事从玄学变成一套可执行的策略。

一个面向 AI Agent 的开源技能包（Agent Skill）。装载后，AI 会按一套完整的五阶段工作流，为品牌产出 GEO（Generative Engine Optimization，生成式引擎优化）策略：先扫描 AI 现在怎么回答，再找到品牌缺席的节点，最后给出有针对性的内容与平台打法。经过真实客户项目反复迭代，当前版本 v4.6。

---

## 这个技能解决什么问题

越来越多消费者的决策起点从搜索引擎变成了 AI 问答。但大多数品牌对「AI 怎么说自己」一无所知：

- 不知道 AI 在回答品类问题时提没提到自己、说的是对是错；
- 想做 GEO，但停留在「发内容等 AI 引用」的误区，没有诊断先行的策略逻辑；
- 定词凭感觉，词表里塞满品牌自嗨的问法，AI 根本不会触发品牌；
- 平台选择凭印象，不知道 Kimi、豆包、DeepSeek 各自的信源偏好差异。

这个技能把一套经过实战验证的 GEO 方法论固化成了 AI 可执行的工作流：**问卷定位 → AI 回答扫描 → 品牌调研 → 机会诊断 → 链路定词 → 策略输出**。

## 谁适合用它

| 人群 | 典型场景 |
|------|----------|
| **公关 / 传播咨询公司** | 把 GEO 作为需求入口撬动传播案；给客户提供 AI 搜索端的品牌诊断与策略 |
| **广告 / 传媒 Agency** | 比稿时加入 GEO 板块，用 AI 回答现状扫描制造「啊哈时刻」 |
| **品牌方市场部 / 公关部** | 摸清自家品牌在 AI 端的可见度与口碑，制定内容铺设方向 |
| **咨询顾问 / 行业研究者** | 需要一套结构化的 GEO 分析框架与定词方法论 |
| **内容团队** | 把通稿、活动记录、履历材料改写成「AI 爱引用」的结构性分发稿 |

## 你会得到什么

根据你选择的策略深度，交付物从轻到重分为四档：

1. **轻量方向**：策略方向清单 + 三层意图示例词（适合初次沟通）
2. **标准研判**：品牌调研摘要 + GEO 机会诊断 + 搜索链路地图 + 策略方向
3. **深度方案**：完整研判 + 内容矩阵 + 执行计划 + 监测方案
4. **可视化交付**：上述内容 + PPT 格式（适合客户汇报）

附带的下游能力：把现成材料改写成 GEO 分发稿（实体统一、可整段引用、中立可验证）。

## 方法论亮点

- **诊断先行**：GEO 的第一步不是生产内容，而是扫描 AI 当前的回答，找到品牌缺席与错误的节点，再做针对性纠正与占位；
- **意图而非关键词**：GEO 优化的对象不是关键词，是消费者意图在 AI 世界的重新表达，按五类决策意图（推荐 / 比较 / 购买决策 / 场景 / 品牌验证）× 两阶段（从知道到入选 / 从入选到偏爱）结构化定词；
- **BTR 预检**：每个示例词先过 Brand Trigger Rate 检验，只出知识不出品牌的问法直接淘汰；
- **语义簇去重**：同义问法是簇内变体而不是多个战场，覆盖度按簇计算，不用句子数虚增工作量；
- **平台有据可依**：基于六大 AI 平台的信源与内容形态偏好快照选 2–3 个核心平台深耕，不做全平台撒网；
- **面向未来**：策略锚定品牌最近的战略信号（官方传播、高管表态、年报），而不是过去产品动作的总结。

## 如何使用

**安装**：将本技能包放入你的 Agent 环境的技能目录（如 Kimi 的 `~/.user/skills/`，或 Claude Code / Cursor 的 skills 目录），重启或刷新即可。

**触发**：直接用自然语言提出需求，例如——

- 「帮我做一个 XX 品牌的 GEO 策略」
- 「 GEO 研判一下我们家品牌在 AI 搜索端的表现」
- 「给我们做个 AI 搜索优化的方向规划」
- 「把这篇通稿转成 AI 喜欢的结构做分发」

AI 会先通过四道定位问卷确认品牌阶段、团队职能、核心目标与交付深度，然后自动执行完整工作流。

## 为什么它不只是一个 Prompt

- **实战沉淀**：方法论来自真实客户项目的多轮迭代（v1 到 v4.6），包括定词踩坑、商务定位、平台选型的教训；
- **流程强制**：五阶段不可跳步，问卷先行，避免 AI 拿到品牌名就套模板；
- **质量红线**：示例词红线、BTR 预检、语义簇去重写死在流程里，不依赖使用者的经验；
- **边界清晰**：`boundary-rules.md` 明确什么该做什么不该做，降低 AI 一本正经编造的风险；
- **可二次开发**：方法论文件在 `references/` 独立维护，可按自己公司的打法改写，主流程不用动。
